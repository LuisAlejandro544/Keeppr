ci(release): configurar workflow de compilación release para pre-releases beta v0.1.0-b y procesamiento de changelog

- Pipeline de CI/CD para APK de Release (`.github/workflows/build-release.yml`):
  * Automatización de compilación de APK en modo Release activada exclusivamente al detectar eventos de Pre-Release de GitHub con etiqueta terminada en sufijo `-b` (ej. `v0.1.0-b`) o mediante ejecución manual (`workflow_dispatch`).
  * Entorno de compilación hermético: Java 17 Temurin, Toolchain de Rust (stable) con targets nativos para arquitecturas Android de 64 bits (`aarch64-linux-android`, `x86_64-linux-android`) y 32 bits (`armv7-linux-androideabi`), CMake 3.22.1 y NDK 26.1.10909125.
  * Inyección segura de credenciales de firma mediante GitHub Secrets (`RELEASE_KEYSTORE_BASE64`, `RELEASE_STORE_PASSWORD`, `RELEASE_KEY_ALIAS`, `RELEASE_KEY_PASSWORD`) con decodificación al vuelo y generación de clave de contingencia autofirmada para evitar fallos de compilación si los secretos aún no han sido cargados.
  * Compilación con `./gradlew assembleRelease` sin caché ni daemon; R8/ProGuard deshabilitado temporalmente (`isMinifyEnabled = false`) para garantizar estabilidad durante el ciclo inicial de pruebas beta.
  * Publicación automática del artefacto (`Keeppr-Release-Beta-v0.1.0-b-APK`) y adjuntado directo del archivo APK generado a la pre-release de GitHub mediante `action-gh-release`.

- Automatización de registro de cambios Beta (`.github/workflows/process-changelog-beta.yml`):
  * Creado flujo de publicación para `Chanelog-beta.md`, activado exclusivamente ante pre-releases con sufijo `-b` o manualmente (`workflow_dispatch`).
  * Inyección automática del contenido íntegro del changelog en las notas de la pre-release en GitHub mediante `softprops/action-gh-release@v2`.

- Optimización del pipeline de depuración (`.github/workflows/build-debug.yml`):
  * Flujo de compilación de APK Debug configurado para ejecución exclusivamente manual (`workflow_dispatch`), evitando consumo innecesario de minutos y ejecuciones automáticas en cada commit o pull request.

- Limpieza de interfaz de usuario en pantalla principal (`NotesListScreen.kt`):
  * Eliminado el diálogo flotante redundante de prueba "Motores Nativos" y su botón con icono de chip en la barra superior de la lista de notas.
  * Se mantiene la ejecución y automatización con Lua 5.4.6 en el editor de notas (`NoteEditorScreen`), donde cumple su función real para plantillas y transformaciones de texto.

- Registro de capacidades y versión oficial Beta (`Chanelog-beta.md` y `app/build.gradle.kts`):
  * Creado el documento `Chanelog-beta.md` detallando las 7 columnas funcionales de Keeppr: cifrado criptográfico AES-256 + PBKDF2 en Rust/C++, soporte multiarquitectura de 32/64 bits, automatización con Lua 5.4.6, editor Markdown táctil, gestión de bóvedas y exportación abierta (.zip/.md), theming Material 3 con colores dinámicos y herramientas de telemetría móvil (FPS HUD, monitor de memoria y visor Logcat).
  * Actualizada la versión oficial de la aplicación a `versionName = "0.1.0-b"` con `versionCode = 1` en `app/build.gradle.kts`.
  * Habilitada la variable de entorno `KEY_ALIAS` en el bloque de `signingConfigs.release`.

- Documentación del repositorio actualizada:
  * Actualizados `README.md`, `ROADMAP.md`, `STRUCTURE.md` y `AI_CONTEXT.md` reflejando la transición a la fase Beta v0.1.0-b, la guía de configuración de GitHub Secrets para la firma de APKs de release y el nuevo flujo de trabajo para pre-releases.
